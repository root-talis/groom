# API reference

This is the reference manual for the `groom` runtime crate. It covers `GroomRouter` composition and typestate, the `OpenApiSpecLayer` trait, content negotiation, cargo features, and public exports.

## GroomRouter

`GroomRouter` is the composition core returned by the `#[Controller]`-generated `into_router()`. It exposes terminal methods only after `.validate()`.

### Typestate

`GroomRouter` is parameterized over two types:

| Type | Meaning | Where it appears |
|------|---------|------------------|
| `GroomRouter<S = (), V = NotValidated>` | `S` is the axum state type; `V` is the validation state | `into_router()`, `merge()`, `nest()`, `layer()`, … |
| `GroomRouter<S, Validated>` | validation passed; terminal methods available | result of `.validate()` |
| `NotValidated` | marker: router not yet validated; terminal methods unavailable | default `V` on construction |
| `Validated` | marker: router validated | `.validate()` result |
| `GroomRouterValid<S = ()>` | alias for `GroomRouter<S, Validated>` | convenient shorthand for signatures |

Terminal methods (`to_axum_router`, `to_openapi`) exist only on the `Validated` variant. Calling them on an unvalidated router fails at compile time.

### Methods

**`GroomRouter::new()`** — creates an empty router.

```rust
impl<S: Clone + Send + Sync + 'static> GroomRouter<S, NotValidated> {
    pub fn new() -> Self
}
```

**`controller::into_router()`** — generated by `#[Controller]` for every controller module (see the [user guide](user-guide.md)). Returns the controller's routes as a `GroomRouter` ready for composition.

```rust
pub fn into_router() -> GroomRouter<S>
```

`S` is the controller's `state_type` (default `()`); the validation state defaults to `NotValidated`.

**`merge(other)`** — merges the axum router, concatenates OpenAPI paths, and merges the `ComponentsRegistry`. Identical schemas merge without error. The same schema name with *different* types produces `MergeError::SchemaConflict`.

```rust
pub fn merge(self, other: GroomRouter<S, NotValidated>) -> Result<Self, MergeError>
```

**`nest(path, other)`** — nests the axum router and prefixes OpenAPI paths (`prepend_path`). Conflict rules match `merge()`.

```rust
pub fn nest(self, path: &str, other: GroomRouter<S, NotValidated>) -> Result<Self, MergeError>
```

**`layer(layer)` / `route_layer(layer)` / `fallback(handler)`** — delegate to the inner axum router and return `Self`.

```rust
pub fn layer<L>(self, layer: L) -> Self
where
    L: tower::layer::Layer<axum::routing::Route> + Clone + Send + Sync + 'static,
    L::Service: tower::Service<axum::extract::Request> + Clone + Send + Sync + 'static,
    <L::Service as tower::Service<axum::extract::Request>>::Response: axum::response::IntoResponse + 'static,
    <L::Service as tower::Service<axum::extract::Request>>::Error: Into<std::convert::Infallible> + 'static,
    <L::Service as tower::Service<axum::extract::Request>>::Future: Send + 'static;

pub fn route_layer<L>(self, layer: L) -> Self
// same bounds as `layer()`

pub fn fallback<H, T>(self, handler: H) -> Self
where
    H: axum::handler::Handler<T, S>,
    T: 'static;
```

**`layer_with_spec(spec_layer)`** — mounts the layer on the request pipeline and registers it for OpenAPI contribution. See [`## OpenApiSpecLayer`](#openapispeclayer).

```rust
pub fn layer_with_spec<SL>(self, spec_layer: SL) -> Self
where
    SL: OpenApiSpecLayer + Clone;
```

**`with_state(state)`** — available on `GroomRouter<(), NotValidated>`. It retypes the router's state. `S2` is inferred from the context where the router is consumed.

```rust
pub fn with_state<S2: Clone + Send + Sync + 'static>(self, state: ()) -> GroomRouter<S2, NotValidated>
```

**`validate()`** — detects route shadowing, where more than one controller registers the same method + path. Returns the `Validated` router, or a `RouterValidationError`.

```rust
pub fn validate(self) -> Result<GroomRouter<S, Validated>, RouterValidationError>
```

**`to_axum_router()`** — Validated only. Consumes the router and returns the inner axum router.

```rust
pub fn to_axum_router(self) -> axum::Router<S>
```

**`to_openapi(api)`** — Validated only. Merges the router's paths and components into a base spec you provide. The base `OpenApi` carries info, tags, security, and servers. Groom adds `paths` and `components.schemas` and preserves the rest.

```rust
pub fn to_openapi(&self, api: utoipa::openapi::OpenApi) -> OpenApi
```

### Errors

Both error types are `thiserror`-based and implement `Debug`, `Clone`, and `std::error::Error`.

**`MergeError`** — returned by `merge()` and `nest()`:

```rust
#[derive(Debug, Clone, Error)]
pub enum MergeError {
    SchemaConflict {
        name: String,
    },
    SchemaNotFound {
        path: String,
        registry: String,
    },
}
```

- `SchemaConflict` — the same schema name was registered with different types on the two sides being merged. The variant carries only the schema `name`. Identical schemas are accepted.
- `SchemaNotFound` — a schema reference could not be resolved inside the given `registry`.

**`RouterValidationError`** — returned by `validate()`:

```rust
#[derive(Debug, Clone, Error)]
pub enum RouterValidationError {
    RouteShadow {
        path: String,
        method: ::http::Method,
    },
}
```

- `RouteShadow` — the same method + path was registered by more than one controller.

### Composition semantics

`merge()` and `nest()` are the composition primitives. Both concatenate OpenAPI paths and merge the `ComponentsRegistry` (raising `SchemaConflict` on name/type mismatch). `nest()` also prefixes the nested router's paths. A spec layer stays attached to the paths it was registered on. Shadowing is only detectable after composition, so `validate()` must run before `to_axum_router()` and `to_openapi()`. It catches duplicate method + path registrations that axum would otherwise tolerate silently.

## Public exports

The `core` and `traits` modules are `pub(crate)`. Their public types are re-exported at `groom::router::*`.

| Export | Kind | Notes |
|--------|------|-------|
| `GroomRouter` | struct | the composition core documented above |
| `GroomRouterValid<S = ()>` | type alias | `GroomRouter<S, Validated>` |
| `NotValidated` | marker struct | default validation state |
| `Validated` | marker struct | state after `.validate()` |
| `OpenApiSpecLayer` | trait | middleware + spec contribution (below) |
| `MergeError` | enum | merge/nest conflict errors |
| `RouterValidationError` | enum | `validate()` errors |

Top-level public modules of the `groom` crate (`groom/src/lib.rs`):

| Module | Contents |
|--------|----------|
| `groom::extract` | `GroomExtractor`, `ComponentsRegistry`, request-body extractors |
| `groom::response` | `Response` trait and response machinery |
| `groom::content_negotiation` | `Accept` / `Content-Type` parsing (see below) |
| `groom::json_ptr` | RFC 6901 JSON Pointer escaping utilities |
| `groom::runtime_checks` | runtime validation helpers (e.g. distinct response codes) |
| `groom::router` | `GroomRouter`, `OpenApiSpecLayer`, errors — the subject of this document |

## OpenApiSpecLayer

`OpenApiSpecLayer` extends `tower::Layer` in concept. ONE type implements both the runtime middleware (via `mount`) and the OpenAPI spec contribution, which removes two types and two arguments. `layer_with_spec()` applies the layer to the request pipeline and stores it for spec generation.

### Trait definition

```rust
pub trait OpenApiSpecLayer: Send + Sync + Clone + 'static {
    /// Whole-spec modification; default no-op. Called once per unique spec layer
    /// during `GroomRouter::to_openapi()`.
    fn modify_openapi(&self, _api: &mut utoipa::openapi::OpenApi) {
        // Default: do nothing
    }

    /// Per-(path, method) modification; default no-op. Called BEFORE `modify_openapi`.
    fn modify_operation(
        &self,
        _path: &str,
        _method: &utoipa::openapi::path::HttpMethod,
        _operation: &mut utoipa::openapi::path::Operation,
    ) {
        // Default: do nothing
    }

    /// Clone this spec layer into a type-erased box for storage.
    fn clone_box(&self) -> Box<dyn SpecLayerModifier> {
        Box::new(self.clone())
    }

    /// REQUIRED — mount this spec layer into axum::Router through layer.
    fn mount<S>(&self, r: axum::Router<S>) -> axum::Router<S>
    where
        S: Clone + Send + Sync + 'static;
}
```

- `modify_openapi` — whole-spec modification; default no-op. Called once per unique spec layer during `to_openapi()`. Use it to add security schemes, response codes, or other metadata.
- `modify_operation` — per-(path, method) operation modification; default no-op. Called before `modify_openapi`. Use it to add per-operation metadata such as `security` requirements.
- `clone_box` — type-erased clone so `GroomRouter` can store and clone layers. The default delegates to `Clone`; no override needed.
- `mount` — **REQUIRED**. The tower-layer hook that applies this layer to the axum router (runtime behavior).

### Composition semantics

- `merge()` — layers from both routers are preserved.
- `nest(path, other)` — the nested router's layers stay attached to its paths, now under the mount prefix.
- `layer_with_spec()` — mounts the layer on the request pipeline and applies it to every path registered so far.

### Example

```rust
use groom::router::{GroomRouter, OpenApiSpecLayer};

struct MyLayer;

impl tower::Layer<axum::routing::Route> for MyLayer {
    type Service = /* your tower Service type */;

    fn layer(&self, inner: axum::routing::Route) -> Self::Service {
        // Wrap inner with your middleware
    }
}

impl OpenApiSpecLayer for MyLayer {
    fn modify_openapi(&self, api: &mut utoipa::openapi::OpenApi) {
        // Add security schemes, response codes, etc.
    }
}

let router = GroomRouter::new()
    .layer_with_spec(MyLayer);
```

See [auth-middleware example](../examples/auth-middleware/) for a complete working example.

## Content negotiation

The public API in `groom::content_negotiation` parses request headers and maps content types:

```rust
pub fn parse_accept_header(headers: &HeaderMap) -> Result<Option<Accept>, HeaderParseError>      // Accept: from the accept-header crate
pub fn parse_content_type_header(headers: &HeaderMap) -> Result<Option<Mime>, HeaderParseError>  // Content-Type: from the mime crate
pub fn get_body_content_type(mime: Option<Mime>) -> Option<BodyContentType>                      // map to the enum below

#[derive(Debug, Clone, Error)]
pub enum HeaderParseError {
    UnparseableValue(&'static str, String),
    NonUtf8HeaderBytes(&'static str),
}

#[derive(Debug)]
pub enum BodyContentType {
    Json,
    FormUrlEncoded,
}
```

- `HeaderParseError` — shared by both header parse functions. `UnparseableValue(header, value)` — the header value failed to parse as the expected type; `NonUtf8HeaderBytes(header)` — the header value is not valid UTF-8.
- `parse_accept_header` — parses the `Accept` header into an `accept_header::Accept`; `Ok(None)` means the header is absent. `Err` means the header is malformed — handled as `400 Invalid Accept header.` by generated wrappers.
- `parse_content_type_header` — parses the `Content-Type` header into a `mime::Mime`; `Ok(None)` means the header is absent. `Err` means the header is malformed — mapped to the generated `BadContentType` rejection by request-body extractors.
- `get_body_content_type` — maps a parsed Mime to a `BodyContentType`. JSON detection accepts both `application/json` and `application/*+json` (for example `application/vnd.api+json`). Unsupported content types yield `None`; groom's request-body extractors answer `400` with a plain-text error.

On the response side, generated controller wrappers call the return type's `__groom_negotiate_content_type` **before** invoking the handler. An `Accept` that matches none of the type's supported content types yields `406 Not Acceptable` with a `Vary: Accept` header and a body listing the supported types (`Supported content types: ...`); a malformed `Accept` yields `400` with `Invalid Accept header.`. The request-body `400` from groom's extractors is about `Content-Type` handling and is unchanged.

## Integrating with an existing router and OpenAPI spec

Groom composes multiple controllers and merges into infrastructure you already have.

**Router** — start from the `GroomRouter` returned by a controller's `into_router()`. Compose controllers via `.merge()` and `.nest()`, then validate and convert to an axum `Router`:

```rust
let router = todos::into_router();
let router = other_controller::into_router().merge(router).unwrap();
let router = router.layer(Extension(app.task_service));

// Convert for axum:
let axum_router = router.validate().unwrap().to_axum_router();
```

**OpenAPI** — start from a utoipa `#[derive(OpenApi)]` struct for API metadata (title, version, contact, security schemes, tags). Then generate the spec from `GroomRouter`:

```rust
#[derive(OpenApi)]
#[openapi(
    info(title = "TODO example", version = "0.0.1"),
    // tags, servers, security, …
)]
struct ApiDoc;

let spec = todos::into_router()
    .validate()
    .unwrap()
    .to_openapi(ApiDoc::openapi());
```

The base `ApiDoc` and Groom controllers share one spec. Groom adds `paths` and `components.schemas`; utoipa retains global metadata. Multiple controllers chain via `.merge()` on `GroomRouter` the same way.

See how the [hello-world](../examples/hello-world/src/main.rs) example serves the merged YAML at `/spec.yaml` via an axum `Extension`. The [todo example](../examples/todo/backend/src/controller/mod.rs) gates this behind a `--serve-spec` flag.

## Companion spec binary

Place a small binary next to the main server crate to export OpenAPI without starting HTTP. The [todo example](../examples/todo/backend/src/bin/spec.rs) writes the same spec the server would use:

```rust
// src/bin/spec.rs
use groom_example_todo_backend::controller::make_spec;

fn main() -> color_eyre::eyre::Result<()> {
    color_eyre::install()?;
    print!("{}", make_spec()?.get());
    Ok(())
}
```

`make_spec` lives in the library crate and shares the same `GroomRouter::to_openapi()` path as the server:

```rust
pub fn make_spec() -> Result<String> {
    #[derive(OpenApi)]
    #[openapi(info(title = "TODO example", version = "0.0.1"))]
    struct ApiDoc;

    let spec = todos::into_router()
        .validate()?
        .to_openapi(ApiDoc::openapi())
        .to_yaml()?;
    Ok(spec)
}
```

Build and run:

```sh
cargo run --bin spec > spec.yaml
```

See how the [todo example justfile](../examples/todo/justfile) defines `generate-api-spec` and runs it before `generate-api-client`. The client runs `npm run generate:api` (orval against `spec.yaml`), configured in [orval.config.ts](../examples/todo/frontend/orval.config.ts).

### Suggested contract-first workflow

1. **Define stubs** — Backend and frontend agree on controller modules with handler signatures, DTOs, and response enums. Implement handlers with `todo!()` or minimal placeholders.
2. **Generate spec** — Run the spec binary; commit `spec.yaml` (or JSON) to the repository.
3. **Review** — Both teams review the generated OpenAPI document. Adjust the Rust types (field names, variants, status codes, doc comments) until the contract is acceptable. Regenerate until approved.
4. **Parallel implementation** — Frontend generates a client from the committed spec (for example [orval](https://orval.dev) as in [todo/frontend](../examples/todo/frontend)). Backend fills in service and repository logic. Both sides stay aligned to one source of truth.
5. **CI** — Add a check that `cargo run --bin spec` output matches the committed file, so API changes are explicit in diffs.

The spec derives from Rust types. Refactors that break the contract fail at compile time on the backend. The committed spec diff signals breaking changes to the frontend.
